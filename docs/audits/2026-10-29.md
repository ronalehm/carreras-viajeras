## Dependencias

`npm audit --package-lock-only` señaló 22 paquetes afectados en el grafo completo:
12 de gravedad alta, 9 moderada y 1 baja; ninguna crítica. Con `--omit=dev` quedaron
dos paquetes de producción afectados, ambos de gravedad alta. Los paquetes y
avisos transitivos se solapan: no son 22 vulnerabilidades independientes.

La revisión conserva [el resultado completo](2026-10-29/dependencies-all.json) y
[el resultado de producción](2026-10-29/dependencies-production.json), obtenidos
del registro npm durante esta auditoría. Ambas consultas finalizaron con código 1
por los avisos; no se describen como comprobaciones correctas.

Remediación recomendada: actualizar de forma selectiva a una versión corregida de
Zod (el aviso excluye 4.6.6 y posteriores) y de follow-redirects (1.16.1 o posterior),
comprobando la resolución de axios y repitiendo los tests y build. Evaluar aparte
las cadenas de desarrollo OpenNext/minificación, Wrangler/Miniflare, MCP/shadcn,
Drizzle/esbuild y Vite. `npm audit fix --force` propone incluso downgrades de
herramientas y no es una resolución revisada. No se cambiaron package.json ni el
lockfile para ocultar avisos o introducir actualizaciones ajenas a la integración.

## Límites operativos y siguientes verificaciones

Faltan `DATABASE_URL`, `CLERK_SECRET_KEY` y `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` de
desarrollo en la máquina. Sin esos valores no se verificaron sesiones reales,
interfaz autenticada, aceptación de invitaciones, perfiles ni lectura real de Neon.
No se afirma conformidad WCAG completa: navegación, contraste, lector de pantalla
y dispositivos requieren comprobación en navegador real.

La red actual bloquea Google Fonts y la API de GitHub. Los dominios necesarios
quedaron solicitados en el borrador del entorno; guardarlos allí no aplica ni
publica la configuración. Git HTTPS sí permitió actualizar las ramas de ambos PR;
su estado, aprobación, descripción, CI y cierre/fusión no se pueden confirmar por
esa operación de Git. Las descripciones preparadas se conservan para actualización
cuando la API esté disponible.

La revisión nativa de Codex en GitHub necesita activación y acceso en sus ajustes.
Los archivos del proyecto no la activan ni sustituyen las políticas administradas
del host. Ver [guía de Codex](../CODEX.md).

No se aplicaron migraciones en Neon, no se crearon identidades/roles remotos y no
se desplegó ni publicó Cloudflare. Para cerrar la validación operativa faltan red,
credenciales de desarrollo, build/Worker, flujos autenticados y una prueba real de
la carrera de ofertas. Las remediaciones de dependencias se gestionan explícitamente
como trabajo pendiente, con sus verificaciones propias.
